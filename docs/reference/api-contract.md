# API contract reference

Do not edit by hand. Generated by synthesizing the CDK app in `backend/bin/backend.ts` and
reading every `AWS::ApiGatewayV2::Route` out of the resulting CloudFormation templates.
Regenerate with:

```
cd backend && npm run gen-api-contract
```

`api-contract-reference.test.ts` fails the build when this file stops matching a fresh render,
so a route added to a stack is a route added here.

For what a client must DO with these routes - how to authenticate, which limits apply, what a
refusal looks like - read [the API guide](../guides/developer/API-GUIDE.md). This file is the
inventory, not the instructions.

**What a row proves, exactly:** that the deployed gateway serves this method at this path with
this authorizer. It does not describe the request or response body. No route declares a request
model, so the shape of a request is enforced by the handler behind it and cannot be read off the
template.

**CORS is the API's own.** Each API answers every preflight and adds its configured headers to the
responses it returns, echoing the one allowed origin a request names; a handler's own CORS headers
are not what a browser sees. Whether a refusal the gateway answers itself (an authorizer's 401 or
403, a throttle's 429) carries them is a property of the deployed API rather than of the template,
and is checked against the deployed APIs. These variants set neither `appUrl` nor `adminAppUrl`,
so the origins below are the development defaults; a deployment lists its own.

Deployment shapes synthesized to produce this file: `athena`, `aurora`, `athena+second-issuer`, `athena+guest`, `athena+invitation-link`, `aurora+sleep`.

## Routes

Grouped by API. `Authorizer` is what a deployment taking every default serves: `AWS_IAM` is a
SigV4-signed call, and the edge authorizer verifies a bearer token from a trusted issuer.
`Throttle` is the route's own limit, or the stage's. `Integration` is the construct id of the
Lambda behind the route, which is how to find the handler in `backend/lambda/src/`.

## What this reference does not carry

- **Base URLs.** Each API's invoke URL is minted at deploy time and published as a stack output
  (`PersonApiUrl`, `AdminApiUrl`). Resolve them from the deployed stacks, never by composing an id.
- **Request and response bodies.** No route declares a request model, so nothing in the template
  describes a body. The guide documents the shapes that were read from the handlers, and says
  which ones were not.
- **The per-user limits.** The throttles above are per route and per second. The hourly request
  limit and the spend budgets are enforced behind the gateway, in the assistant path, and are
  described in the guide.
